# 剪映草稿加解密（默认做法的根基；全局规矩见 SKILL.md「剪映怎么对待」）

## 原理
- 剪映 6.0 起，草稿里的 `draft_content.json`（时间线）和 `draft_meta_info.json`（草稿名、路径）是密文（AES-GCM，密钥在剪映自己的 `videoeditor.dll` 里，外面算不出来）
- 不自己解：`scripts/jianying/jycrypto.py` 用 Python 自带的 ctypes 加载剪映安装目录里的 `videoeditor.dll`，直接调它导出的三个函数（解密 decrypt、加密 encrypt、打开加密 enable），让剪映自己加解密。做法来自 github.com/wenshui330/jy-draftc（MIT）
- 数据按 C++ std::string 的内存样子传进去；同样的内容每次加密出来不一样（带随机数），解回来一样
- 剪映安装目录从注册表的卸载信息里取（`Uninstall\JianyingPro` 的 UninstallString、DisplayVersion），不写死路径
- 实测可用：剪映专业版 11.5.0.14471（2026-10-10）

## 用之前先自检（draft.py 菜单 5）
- jycrypto 建好时自动自检：加密一段文字再解回来要一字不差；菜单 5 再解开草稿目录里最近的一个加密草稿
- 过了就按默认做法走；没过就按下面处理，还不行才转兜底
- 读写草稿前剪映必须完全退出（关窗口，不只是回首页）。剪映 11.5 同一份时间线存了好几处（草稿根目录和 `Timelines/<时间线 id>/` 里各有 draft_content.json、.bak、template-2.tmp），jydraft 会把内容一样的几处一起改；jydraft 写完会重读核对

## 失效时怎么办（按顺序，解决一步就停）
1. 看报错是哪一类：
   - 注册表没有剪映 → 电脑上没装剪映专业版，让用户装
   - 加载不了 dll → 多半是剪映升级后安装目录里版本目录变了，看 `jycrypto.install_dir()` 找到的目录对不对
   - 找不到原来的函数 → 剪映改了函数名。报错里会列出 dll 导出函数中名字带 EncryptUtils 的（`jycrypto.exports()`），找名字里有 decrypt、encrypt、enable 的新名字换进 `SYM_DEC`、`SYM_ENC`、`SYM_ENABLE`；参数个数变了（名字里 AEBV34 的个数）就照新名字调 argtypes
   - 解密成功但不是 JSON、或自检对不上 → 剪映换了加密方式，查 github.com/wenshui330/jy-draftc 有没有跟进，有就照它改
2. 改完在草稿副本上试（复制一个草稿到工作目录的 `工程文件/临时文件/`，解密 → 改 → 加密 → 再解密），别直接动用户的草稿
3. 解决了：更新用户电脑上本 skill 的 `scripts/jianying/jycrypto.py`（这是用户定的规矩，不算擅自改 skill），把剪映版本和改了什么记进本文件「实测可用」
4. 没解决：转兜底（剪映操作.md 各步标「兜底」的做法），在 `工程文件/问题记录.md` 记下剪映版本和报错

## 跟用户怎么说
