# Mac：OpenChatCut 操作

Mac 上用到编辑软件的几步（第 1、3、4 步，和用户要把成片放进项目时）怎么做；Mac 和 Windows 怎么分工见 SKILL.md「Mac 的编辑软件」，两边相同的规矩只写在 SKILL.md 和这里引用的地方，这里只写 Mac 不一样的。

## 连接（第 1 步就连好）

- 没装的照 `装软件.md`「OpenChatCut」装；开工检查会查装没装。
- 连接由用户在 AI 客户端里配：在 OpenChatCut「设置 → MCP」取得当前地址和令牌，配成所用 AI 客户端的 Streamable HTTP MCP 服务；默认地址是 `http://localhost:5199/api/external-mcp/mcp`。令牌只放在客户端的环境或密钥配置里，不发进对话，也不写进 skill 或视频工作目录。Codex、Claude Code 和其他支持 MCP 的客户端都能用。请用户配的话见引导语.md「Mac 使用 OpenChatCut 时的引导语」。
- 查连上没有：调用 `openchatcut_status`。AI 这边没有 OpenChatCut 的工具，或调用报连接错误，就是没连上，请用户配好；配好后还是没有这些工具，多半要重开 AI 才认得新连接，先把进度记录写好（SKILL.md「衔接」），再请用户重开。
- AI 在浏览器编辑页直接导入本地配音或成片前，确认视频工作目录已列在 `~/Library/Application Support/OpenChatCut/.env.local` 的 `AGENT_IMPORT_ROOTS` 中；未列入时只补这一项并重启 OpenChatCut。它接受逗号分隔的绝对目录。桌面离线编辑可直接导入，浏览器编辑页未授权会报 `IMPORT_ROOTS_NOT_CONFIGURED`。
- 每次编辑：编辑项目时调用 `list_projects`，按进度记录中的项目 ID 定位；没有项目才 `create_project`。调用 `target_project`、`begin_edit_session`、`read_project`，修改后 `review_edit_session`，确认 `get_edit_session` 为 `applied`。编辑会话一律用 `approvalMode: "auto"`，改动直接应用，不等用户在 OpenChatCut 里点批准（用户定的）。需要编辑器里的工具时，打开目标项目的 `editorUrl`。项目 ID 和名称记入 `工程文件/进度记录.md`，下次继续使用同一项目。

## 第 3 步：取得配音

- 照引导语.md「Mac 使用 OpenChatCut 时的引导语」问四选一：A1 文本朗读、A2 自己录、B 已有配音、不要配音。不主动推荐 OpenChatCut 自带的配音；用户问到时再说明怎么配置。
- 选 A1 或 A2：用户在 Mac 剪映里新建草稿、导入初版 SRT（`工程文件/<文稿名>_初版.srt`），生成朗读或录音，再导出音频（WAV）和字幕（SRT）到工作目录顶层；一条消息只让用户做其中一件，话术见引导语.md 同一节。剪映草稿 AI 不读写，也不用让用户退出剪映。
- 选 A1 或 A2、用户没装剪映：照引导语.md「没装剪映」给官网下载页，装好再做上面的。
- 选 B：用户把配音文件放进工作目录顶层；查到文件后再问一句要不要加速（引导语.md「第 3 步 B 问加速」），用户说已经加速过或不用加速，这一步才算完成。
  - 要加速：AI 在 OpenChatCut 新建本视频项目（或按进度记录继续同一项目），`import_asset` 导入配音，按用户说的倍数给配音片段设变速，请用户打开项目试听（引导语.md「Mac 第 3 步 B 试听加速」）；要换倍数就改了再请用户听，直到用户说可以。
  - 定稿后出最终配音：先看 OpenChatCut 能不能把音频轨导出成 WAV（本 skill 还没验证过，以正在运行的 MCP 工具说明为准）；不能就用 ffmpeg 按同一倍数从原配音做出加速版（`atempo`，时长和项目里一致），放工作目录顶层。进度记录写清：加了几倍、最终配音文件名。
  - 第 4 步对齐用这条最终配音，原来放进来的文件不再用。
- 改成不要配音：照剪映操作.md 第 3 步「用户改成不要配音」（两边一样）。

## 第 4 步：对齐配音和字幕

守住 SKILL.md 第 4 步「核心」。先在 OpenChatCut 新建本视频项目，或按进度记录继续同一项目（见「连接」）。

- A1 文本朗读：AI 跑 `export_align.py` 菜单 1（工具用法.md「export_align.py 菜单」），用顶层导出的音频和字幕去空白、字幕跟着配音，出 `工程文件/配音.wav`、`字幕.srt`，同时和初版 SRT 比出用户改了哪些字幕。菜单 1 停下时（有字幕没有配音、第一条字幕前面有声音），说清是哪几条，请用户在剪映里补上或删掉、重新导出。对齐好的配音和字幕再导进项目给用户看。
- B 配音自带每句或每字的时间戳（TTS 工具生成时给的）：直接按时间戳写字幕，不用再逐句核对；匀速加速过的，时间戳按新旧时长的比例缩放后用（剪过、分段变速的不能这样算）。
- A2 自己录、B 现成配音：配音和字幕不是一一对应，AI 在 OpenChatCut 里对齐：用 `import_asset` 导入原配音，按当前 SRT 建立字幕，用时间线和转录工具核对每句，把配音、字幕排到一致；每段长度以实际配音为准。对好后用 `read_project` 读出字幕文字和时间写成 `工程文件/字幕.srt`；`工程文件/配音.wav` 按项目里每段配音在原文件里的起止和在时间线上的位置，用 ffmpeg 从原配音拼出来，不从项目导出 MP3（MP3 有损，开头还会多一小段静音，字幕会整体错开）。核对两份文件与项目一致。
- 字幕怎么放进项目：当前版本没有经本 skill 验证的直接 SRT 导入接口；可先用 `edit_track` 建独立视频轨，再用 `edit_item` 按 SRT 时间创建可编辑的文字片段，读回确认轨道和时间。
- 用户确认：请用户打开项目从头听看（引导语.md「Mac 使用 OpenChatCut 时的引导语」）。用户说哪里不对：A1 要重新生成配音的，请用户在剪映里重新生成、重新导出，重跑菜单 1 再导进项目；只改字的，和 A2、B 要调的，AI 在项目里改，同时更新 `字幕.srt`、`配音.wav`。
- 收尾检查：A1 菜单 1 已经比过；A2 跑 `export_align.py` 菜单 2，选 `字幕.srt` 和初版 SRT 比；B 不做。核对时长、查出改动后怎么办，照剪映操作.md「对齐好之后」第 1 项和第 4 项「查出来怎么办」（两边一样）。
- 后续用户又改了项目里的配音或字幕，先读回修改，再按 SKILL.md「字幕是基准」和改稿规则更新动画。不要从旧 SRT 覆盖用户在项目里的新修改。

## 用户要把成片放进项目（不在流程里，用户提了才做）

- 放进第 4 步建的那个项目；没建过项目的（如不要配音的视频）新建一个。
- 用 `import_asset` 把最新的无字幕版成片（`<片名>_<序号>.mp4`）导入同一项目，从 0 秒放进视频轨、在字幕下面；项目里原来的配音轨静音（成片里已经混好人声、配乐、音效）。
- 项目里的字幕和本稿 `字幕.srt` 核对，不一致的改成一致，告诉用户改了哪几句（SKILL.md「字幕是基准」）；视频比配音长的稿，本稿 `字幕.srt` 的时间已经往后挪过，项目字幕的时间也改成和它一致（配音轨已静音，不用挪）。
- 改稿后把项目里的旧版成片换成新版，项目保留，用户可以再打开编辑。

## 结果检查

每次编辑后重新读取项目，确认文字、音频和视频片段确实写入；再次打开项目时先读当前内容再继续。OpenChatCut 的版本或工具接口有变化时，以正在运行的 MCP 工具说明为准。
若 MCP 能列出项目但编辑会话超时，先关闭该项目失效的浏览器标签，重新打开项目；需要时重启 OpenChatCut 并重新连接令牌。
